# Pre-launch security review — 2026-07-22

Scope: the TypeScript API and domain packages, PostgreSQL migrations and row-level-security policies, authentication and API-key paths, envelope encryption, audit metadata, and production-facing HTTP defaults through commit `HIMI-30`.

## Automated and focused review evidence

- `npm audit --omit=dev`: no known production dependency vulnerabilities.
- Repository credential-pattern scan for private-key blocks, AWS access keys, GitHub tokens, and OpenAI-style keys: no matches in tracked files.
- Source scan for dynamic evaluation, process execution, browser HTML injection, console logging, and raw request-header handling: no dynamic-code/process/HTML sinks or application console logging. Credential headers are read only by the authentication hook and never copied into audit metadata.
- Unit and PostgreSQL integration suites cover Argon2id password hashing, secure cookies and CSRF, session and API-key expiry/revocation, account/IP login throttling, API key/IP request throttling, current-membership checks, central RBAC, protected environments, cross-project and cross-tenant denial, forced RLS, append-only/redacted audit events, AES-256-GCM nonce uniqueness and tamper detection, DEK rotation, and reversible migrations.

## Findings fixed in this review

1. API responses lacked explicit browser security policy headers. All API and error responses now receive the hardened header set and no-store caching; integration tests assert every value.
2. Password verification had no brute-force throttle. Login now uses independent hashed-account and IP fixed-window counters (five failures per 15 minutes by default), rejects at the threshold, avoids further Argon2 work while blocked, clears successful identities, and has deterministic unit/integration coverage.

## Residual risks and deployment requirements

- Request and login counters are process-local. A multi-replica deployment must replace them with a shared atomic limiter (for example PostgreSQL or Redis) and configure trusted-proxy IP handling; the single-process deployment is protected now.
- TLS termination, certificate renewal, and HTTP-to-HTTPS redirection are ingress responsibilities. HSTS is emitted by the API but is effective only over HTTPS.
- Managed deployments must keep the KEK in KMS/HSM and restrict workload identity access. Self-hosted installations must mount the 32-byte master key separately from the database and backups.
- The later web application must define a UI-specific CSP (ideally nonce/hash based). The current `default-src 'none'` policy is intentionally correct for the JSON-only API.
- CI provenance, artifact signing, encrypted backup restore drills, production alerting, and distributed metrics are delivery controls tracked by deployment/test issues rather than application-code controls.
- The repository requires Node.js 22. Local validation currently emits an engine warning under Node.js 20, so release CI must enforce the declared Node.js 22 runtime.

No unresolved application-code vulnerability was identified in the reviewed scope.
